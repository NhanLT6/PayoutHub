Hướng dẫn này viết cho bot Teams chạy trên .NET Framework (Web API controller, đặt cạnh app WebForms), dùng các gói thế hệ Bot Builder v3 như Microsoft.Bot.Connector.Teams. Microsoft đã kết thúc hỗ trợ Bot Framework SDK ngày 31/12/2025 và archive repo. Kiểm tra lần cuối: tháng 11/2026.

Add the Web API route

The bot receives all messages at /api/messages. Register this route in your WebApiConfig.cs (or create it if your project doesn't have one):

C# — App_Start/WebApiConfig.csusing System.Web.Http;

public static class WebApiConfig
{
    public static void Register(HttpConfiguration config)
    {
        // Bot Framework messages endpoint
        config.Routes.MapHttpRoute(
            name:          "BotMessages",
            routeTemplate: "api/messages",
            defaults: new { controller = "Messages" }
        );

        // Keep any existing routes below
        config.Routes.MapHttpRoute(
            name:          "DefaultApi",
            routeTemplate: "api/{controller}/{id}",
            defaults: new { id = RouteParameter.Optional }
        );
    }
}

Register WebApiConfig in Global.asax

Ensure Web API is initialized at startup. Open Global.asax.cs and make sure WebApiConfig.Register is called:

Why each developer needs their own registration

Azure Bot Service has one messaging endpoint per registration. If the whole team shares one, only one tunnel URL can be active at a time — whoever last updated the endpoint "wins". The fix is simple: each developer creates their own free Azure Bot registration and sideloads their own manifest. Zero cost, fully isolated.

Dev Tunnels is a free Microsoft tool — a standalone CLI, not tied to Visual Studio. It works from any terminal including Rider's built-in terminal.

Terminalwinget install Microsoft.devtunnel
04

Log in and create a persistent tunnel

Unlike ngrok free tier (random URL on every restart), Dev Tunnels gives you a stable named URL that survives restarts. Create it once, reuse it every day.

Terminal# Log in once (Microsoft or GitHub account)
devtunnel user login

# Create a named persistent tunnel (do this once)
devtunnel create my-bot-tunnel --allow-anonymous

# Add your local port (e.g. 44303 for your IIS Express port)
devtunnel port create my-bot-tunnel -p 44303 --protocol https

# Start the tunnel (run this whenever you start dev)
devtunnel host my-bot-tunnel

The output shows your stable public URL, something like:
https://abc123def.use2.devtunnels.ms

ℹ️
Why --allow-anonymous is the right choice here

Dev Tunnels does support token-based access via devtunnel token, but Azure Bot Service has no way to pass a custom X-Tunnel-Authorization header on its outgoing call to your endpoint — it only sends its own Bot Framework JWT in Authorization. Token-based or Entra-based tunnel auth would block Azure Bot Service itself.

--allow-anonymous is safe because the real security layer is the [BotAuthentication] attribute on your MessagesController. Any request that arrives without a valid Bot Framework JWT signed with your AppId + Secret is rejected with HTTP 401 before your code runs. The tunnel is a dumb pipe — authentication is enforced at the application level. The tunnel URL is also a non-guessable random string, so it isn't publicly discoverable. This is the standard pattern used by the official Teams samples.

In the Azure portal, go to your personal bot's Configuration blade → set Messaging endpoint to:
https://abc123def.use2.devtunnels.ms/api/messages
Because the URL is persistent, you only need to do this once — not every time you restart the tunnel.

Setup — Step 4

How Authentication Works

↗ Bot overview (v3 SDK) ↗ Azure Bot registration walkthrough

Authentication here is service-to-service — it's not about the Teams user logging in. It's about your bot and Azure Bot Service proving their identities to each other on every request. You don't implement any OAuth code yourself; the SDK handles it via the [BotAuthentication] attribute.

A

Teams → Azure Bot Service (Teams verifies your app)

When a user interacts with your bot in Teams, the Teams client sends an activity to Azure Bot Service. Teams attaches a JWT signed with Microsoft's keys. Azure Bot Service validates it.

Teams-issued JWT
B

Azure Bot Service → Your Bot (Azure signs the forwarded request)

Azure Bot Service forwards the activity to your /api/messages endpoint. It attaches its own JWT in the Authorization: Bearer ... header, signed using your App ID + Secret.

Bot Framework JWT
C

Your Bot validates the incoming JWT

The [BotAuthentication] attribute (from the SDK) intercepts every request to MessagesController. It reads MicrosoftAppId and MicrosoftAppPassword from Web.config, validates the JWT, and rejects unauthenticated requests automatically.

[BotAuthentication] attribute
D

Your Bot → Azure (your bot signs outgoing messages)

When you call ConnectorClient to send messages, the SDK internally fetches a token using your AppId + Password via the OAuth 2.0 client credentials flow, and attaches it to the outgoing request. Azure Bot Service validates it before relaying to Teams.

OAuth 2.0 Client Credentials
✅
Summary — what you actually need to do

Add the two keys to Web.config and decorate your controller with [BotAuthentication]. The SDK does everything else. You never write token exchange code yourself.

MessagesController — Your Bot's Inbox

↗ Official C# sample (v3) ↗ Bot overview (v3 SDK) ↗ Cards & actions (v3)

All communication from Azure Bot Service arrives at this single controller as HTTP POST requests. The [BotAuthentication] attribute validates the JWT on every request before your code runs. The activity.Type property tells you what kind of event it is.

C# — Controllers/MessagesController.cs (full implementation)using System;
using System.Net;
using System.Net.Http;
using System.Text;
using System.Threading.Tasks;
using System.Web.Http;
using AdaptiveCards;
using Microsoft.Bot.Connector;
using Microsoft.Bot.Connector.Teams;
using Newtonsoft.Json;
using Newtonsoft.Json.Linq;

[BotAuthentication]  // validates every incoming JWT — rejects with 401 if invalid
public class MessagesController : ApiController
{
    private readonly IConversationStore _store;
    private readonly BotHelper          _bot;

    public MessagesController(IConversationStore store, BotHelper bot)
    {
        _store = store;
        _bot   = bot;
    }

    [HttpPost]
    public async Task<HttpResponseMessage> Post([FromBody] Activity activity)
    {
        if (activity == null)
            return Request.CreateResponse(HttpStatusCode.BadRequest);

        switch (activity.Type)
        {
            case ActivityTypes.Message:
                // User typed a message to the bot in Teams chat
                await HandleMessageAsync(activity);
                break;

            case ActivityTypes.Invoke:
                // Button click — routes to task/fetch or task/submit
                return await HandleInvokeAsync(activity);

            case ActivityTypes.ConversationUpdate:
                // Bot was added to a chat, or a member joined — store context here
                await HandleConversationUpdateAsync(activity);
                break;
        }

        return Request.CreateResponse(HttpStatusCode.OK);
    }

    // ── Route invoke activities ──────────────────────────────────────────────
    private async Task<HttpResponseMessage> HandleInvokeAsync(Activity activity)
    {
        switch (activity.Name)
        {
            case "task/fetch":
                return await HandleTaskFetchAsync(activity);
            case "task/submit":
                return await HandleTaskSubmitAsync(activity);
            default:
                return Request.CreateResponse(HttpStatusCode.OK);
        }
    }

    // ── ConversationUpdate: store context so we can proactively message later ──
    private async Task HandleConversationUpdateAsync(Activity activity)
    {
        // Fires when the bot is first added to a conversation
        if (activity.MembersAdded != null)
        {
            foreach (var member in activity.MembersAdded)
            {
                if (member.Id == activity.Recipient.Id)
                {
                    // Bot was added — save serviceUrl + conversationId for proactive messaging
                    await _store.SaveConversationAsync(new ConversationInfo
                    {
                        ServiceUrl     = activity.ServiceUrl,
                        ConversationId = activity.Conversation.Id,
                        TenantId       = activity.GetTenantId()  // Teams extension method
                    });
                }
            }
        }
    }

    // ── Plain message handler ─────────────────────────────────────────────────
    private async Task HandleMessageAsync(Activity activity)
    {
        using var client = new ConnectorClient(new Uri(activity.ServiceUrl));
        Activity reply = activity.CreateReply("Hello! Use the card in this channel to interact with me.");
        await client.Conversations.ReplyToActivityAsync(reply);
    }

    // ── Full bodies for these two are in the next sections ───────────────────
    // Replace the stubs below with the complete code from Steps 2 and 4.

    private async Task<HttpResponseMessage> HandleTaskSubmitAsync(Activity activity) { /* Step 4 body */ throw new NotImplementedException(); }

This is a Teams-specific extension method from Microsoft.Bot.Connector.Teams. It reads the tenant ID from the Teams channel data in the activity. You need the NuGet package installed for this method to be available.

Foundation

Storing Conversation Context

Before your bot can send a card to Teams proactively, it needs two pieces of information: a serviceUrl (which Azure Bot Service region to use) and a conversationId (which chat thread to post to). Azure Bot Service fills both of these on every activity it sends to your controller — they live on the Activity object as activity.ServiceUrl and activity.Conversation.Id. The catch is that your bot only receives activities when something happens (install event, user message). You must capture and persist them to a database at that point, because there's nothing to read from when you later want to message the user out of the blue.

The three values you must store

ValueWhere it comes fromWhat it's used for
ServiceUrl activity.ServiceUrl Required to create ConnectorClient. Changes by tenant/region — always use the value from the activity, never hardcode it.
ConversationId activity.Conversation.Id Required to send a message to the correct chat thread.
ActivityId Returned by SendToConversationAsync() Required to update a specific message later. Store this when you post the trigger card.

Model + store interface

C#// Models/ConversationInfo.cs — stores the routing context for a user/channel
public class ConversationInfo
{
    public string UserId         { get; set; }  // activity.From.Id — lookup key in the store
    public string ServiceUrl     { get; set; }
    public string ConversationId { get; set; }
    public string TenantId       { get; set; }
}

// Models/ActivityInfo.cs — stores the identity of a specific posted message
public class ActivityInfo
{
    public string ServiceUrl     { get; set; }
    public string ConversationId { get; set; }
    public string ActivityId     { get; set; }
}

// IConversationStore.cs — implement this against your existing DB (SQL Server, etc.)
public interface IConversationStore
{
    Task SaveConversationAsync(ConversationInfo info);
    Task<ConversationInfo> GetConversationAsync(string userId);

    Task SaveActivityInfoAsync(string itemId, ActivityInfo info);
    Task<ActivityInfo> GetActivityInfoAsync(string itemId);
}

When does the bot get context for the first time?

activity.ServiceUrl is a property on every Activity object Azure Bot Service sends to your controller — it arrives pre-filled in the HTTP POST body and the SDK deserialises it automatically. You don't fetch it or look it up; it's just there. The question is only which handler you're inside when you choose to save it:

Both paths give you the same property: activity.ServiceUrl
ConversationUpdate path → inside HandleConversationUpdateAsync(activity) when activity.MembersAdded contains the bot's own ID  ·  Message path → inside HandleMessageAsync(activity) on any normal user message

C# — Controllers/MessagesController.csprivate async Task<HttpResponseMessage> HandleTaskSubmitAsync(Activity activity)
{
    dynamic payload = JsonConvert.DeserializeObject(activity.Value.ToString());
    var data = payload?.data;

    // Read field values — note: Input.Number returns a STRING
    string name     = (string)data?.name;
    int    quantity = int.Parse((string)data?.quantity ?? "0");
    string itemId   = (string)data?.itemId;

    // Multi-select comes as comma-separated string
    var categories = ((string)data?.categories ?? "")
        .Split(new[] { ',' }, StringSplitOptions.RemoveEmptyEntries)
        .ToList();

    // Server-side validation (always do this)
    if (string.IsNullOrWhiteSpace(name) || quantity < 1 || !categories.Any())
    {
        return TaskContinueWithError("Validation failed. Please check your inputs.");
    }

    // Close modal immediately — return {} so the dialog closes
    var closeResponse = Request.CreateResponse(HttpStatusCode.OK);
    closeResponse.Content = new StringContent("{}", Encoding.UTF8, "application/json");

    // Fire-and-forget: close the modal now, process in background
    // _bot.ProcessAndNotify() is implemented in Step 6 — it updates the original card when done
    _ = Task.Run(() => _bot.ProcessAndNotify(itemId, name, quantity, categories));

    return closeResponse;
}

private HttpResponseMessage TaskContinueWithError(string message)
{
    // Re-show the modal with an error message at the top
    var errorCard = new AdaptiveCard(new AdaptiveSchemaVersion(1, 3))
    {
        Body = new List<AdaptiveElement>
        {
            new AdaptiveTextBlock { Text = message, Color = AdaptiveTextColor.Attention }
            // ... same inputs as original card ...
        }
    };

    {
        task = new { type = "continue", value = new { card = new { contentType = "application/vnd.microsoft.card.adaptive", content = JsonConvert.DeserializeObject(errorCard.ToJson()) } } }

    response.Content = new StringContent(JsonConvert.SerializeObject(taskResponse), Encoding.UTF8, "application/json");

}

Task Module — Step 5

Response Patterns for task/submit

↗ Task module overview ↗ Task module from bot

When you receive task/submit you have four choices for what to send back. Pick based on how long processing takes and what the user needs to see.

Option A
✅ Close modal silently

Return HTTP 200 with body {}. Modal closes, no toast. Use when you'll update the original card separately.

Option B
💬 Close + toast message

Return {"task":{"type":"message","value":"Saved!"}}. Modal closes and Teams shows a small notification popup.

Option C
🔄 Show another card

Return task/continue with a new card. Modal stays open. Use for multi-step flows or confirmation screens.

Option D
❌ Re-show with error

Return task/continue with the same card + an error TextBlock at the top. Modal stays open showing the validation error.

💡 Recommended: Use Option A — close immediately, then update the original message card asynchronously. Users get immediate feedback that their action was received, and the card updates in place when processing finishes.

This is ProcessAndNotify() — the method Step 4 fires via Task.Run() after immediately closing the modal. It runs outside the original HTTP request so it can take as long as needed without hitting the 5-second limit. C# — Controllers/MessagesController.csusing System;
using System.Collections.Generic;
using System.Net;
using System.Net.Http;
using System.Text;
using System.Threading.Tasks;
using System.Web.Http;
using AdaptiveCards;
using Microsoft.Bot.Connector;
using Microsoft.Bot.Connector.Teams;
using Newtonsoft.Json;

[BotAuthentication]
public class MessagesController : ApiController
{
    private readonly IConversationStore _store;
    private readonly BotHelper          _bot;

    public MessagesController(IConversationStore store, BotHelper bot)
    {
        _store = store;
        _bot   = bot;
    }

    [HttpPost]
    public async Task<HttpResponseMessage> Post([FromBody] Activity activity)
    {
        if (activity == null)
            return Request.CreateResponse(HttpStatusCode.BadRequest);

        switch (activity.Type)
        {
            case ActivityTypes.Message:
                await HandleMessageAsync(activity);
                break;
            case ActivityTypes.Invoke:
                return await HandleInvokeAsync(activity);
            case ActivityTypes.ConversationUpdate:
                await HandleConversationUpdateAsync(activity);
                break;
        }
        return Request.CreateResponse(HttpStatusCode.OK);
    }

    // ── Invoke routing ────────────────────────────────────────────────────────
    private async Task<HttpResponseMessage> HandleInvokeAsync(Activity activity)
    {
        switch (activity.Name)
        {
            case "task/fetch":  return await HandleTaskFetchAsync(activity);
            case "task/submit": return await HandleTaskSubmitAsync(activity);
            default:           return Request.CreateResponse(HttpStatusCode.OK);
        }
    }

    // ── ConversationUpdate: save context when bot is installed ────────────────
    private async Task HandleConversationUpdateAsync(Activity activity)
    {
        if (activity.MembersAdded != null)
        {
            foreach (var member in activity.MembersAdded)
            {
                if (member.Id == activity.Recipient.Id)
                {
                    await _store.SaveConversationAsync(new ConversationInfo
                    {
                        UserId         = activity.From.Id,
                        ServiceUrl     = activity.ServiceUrl,
                        ConversationId = activity.Conversation.Id,
                        TenantId       = activity.GetTenantId()
                    });
                    using var client = new ConnectorClient(new Uri(activity.ServiceUrl));
                    await client.Conversations.ReplyToActivityAsync(activity.CreateReply("Hi! I'm ready."));
                }
            }
        }
    }

    // ── Message: keep context fresh ───────────────────────────────────────────
    private async Task HandleMessageAsync(Activity activity)
    {
        await _store.SaveConversationAsync(new ConversationInfo
        {
            UserId         = activity.From.Id,
            ServiceUrl     = activity.ServiceUrl,
            ConversationId = activity.Conversation.Id,
            TenantId       = activity.GetTenantId()
        });
        using var client = new ConnectorClient(new Uri(activity.ServiceUrl));
        await client.Conversations.ReplyToActivityAsync(activity.CreateReply("Hello!"));
    }

    // ── Step 2: task/fetch ────────────────────────────────────────────────────
    private async Task<HttpResponseMessage> HandleTaskFetchAsync(Activity activity)
    {
        dynamic payload = JsonConvert.DeserializeObject(activity.Value.ToString());
        string itemId   = payload?.data?.itemId;

        // TODO: replace _yourRepository with your own data-access service
        var options = await _yourRepository.GetOptionsForItem(itemId);
        var card    = _bot.BuildModalCard(options);

        var taskResponse = new
        {
            task = new
            {
                type  = "continue",
                value = new
                {
                    title  = "Settings",
                    height = 400,
                    width  = 500,
                    card   = new
                    {
                        contentType = "application/vnd.microsoft.card.adaptive",
                        content     = JsonConvert.DeserializeObject(card.ToJson())
                    }
                }
            }
        };

        var response = Request.CreateResponse(HttpStatusCode.OK);
        response.Content = new StringContent(JsonConvert.SerializeObject(taskResponse), Encoding.UTF8, "application/json");
        return response;
    }

    // ── Step 4: task/submit ───────────────────────────────────────────────────
    private async Task<HttpResponseMessage> HandleTaskSubmitAsync(Activity activity)
    {
        dynamic payload = JsonConvert.DeserializeObject(activity.Value.ToString());
        var data = payload?.data;

        string name       = (string)data?.name;
        int    quantity   = int.Parse((string)data?.quantity ?? "0");
        string itemId     = (string)data?.itemId;
        var    categories = ((string)data?.categories ?? "")
                              .Split(new[] { ',' }, StringSplitOptions.RemoveEmptyEntries)
                              .ToList();

        if (string.IsNullOrWhiteSpace(name) || quantity < 1 || !categories.Any())
            return TaskContinueWithError("Validation failed. Please check your inputs.");

        _ = Task.Run(() => _bot.ProcessAndNotify(itemId, name, quantity, categories));

        var closeResponse = Request.CreateResponse(HttpStatusCode.OK);
        closeResponse.Content = new StringContent("{}", Encoding.UTF8, "application/json");
        return closeResponse;
    }

    // ── Response helpers — stay here because they use Request (ApiController) ─
    private HttpResponseMessage TaskContinueWithError(string message)
    {
        var errorCard = new AdaptiveCard(new AdaptiveSchemaVersion(1, 3))
        {
            Body = new List<AdaptiveElement>
            {
                new AdaptiveTextBlock { Text = message, Color = AdaptiveTextColor.Attention }
                // TODO: add back the same input fields so the user can correct and resubmit
            }
        };
        return BuildTaskContinueResponse(new { card = new { contentType = "application/vnd.microsoft.card.adaptive", content = JsonConvert.DeserializeObject(errorCard.ToJson()) } });
    }

    private HttpResponseMessage TaskMessageResponse(string text)     // Option B: toast
    {
        return BuildJsonResponse(new { task = new { type = "message", value = text } });
    }

    private HttpResponseMessage TaskContinueWithCard(AdaptiveCard card, string title = "Confirm", int height = 300, int width = 500)  // Option C: new card
    {
        return BuildTaskContinueResponse(new { title, height, width, card = new { contentType = "application/vnd.microsoft.card.adaptive", content = JsonConvert.DeserializeObject(card.ToJson()) } });
    }

    private HttpResponseMessage BuildTaskContinueResponse(object value)
    {
        return BuildJsonResponse(new { task = new { type = "continue", value } });
    }

    private HttpResponseMessage BuildJsonResponse(object body)
    {
        var response = Request.CreateResponse(HttpStatusCode.OK);
        response.Content = new StringContent(JsonConvert.SerializeObject(body), Encoding.UTF8, "application/json");
        return response;
    }
}

    public async Task<IHttpActionResult> NotifyUser(string userId, string itemId)
    {
        // Load routing context saved when the user installed the bot
        var conv = await _store.GetConversationAsync(userId);
        if (conv == null)
            return BadRequest($"User '{userId}' has not installed the bot yet.");

        // All three parameters now resolved
        await _bot.SendTriggerCard(
            conversationId: conv.ConversationId,  // ← from stored ConversationInfo
            serviceUrl:     conv.ServiceUrl,      // ← from stored ConversationInfo
            itemId:         itemId);              // ← from your backend / business logic

        return Ok();
    }
}
