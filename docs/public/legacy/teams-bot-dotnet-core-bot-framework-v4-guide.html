LEGACY. Đọc trước khi dùng.
Hướng dẫn này viết cho bot Teams trên .NET Core / ASP.NET Core dùng Bot Framework SDK v4 (Microsoft.Bot.Builder.*, TeamsActivityHandler, CloudAdapter). Microsoft đã kết thúc hỗ trợ Bot Framework SDK ngày 31/12/2025 và archive repo. Bot đã triển khai trên Azure Bot Service vẫn chạy, nhưng không còn bản vá. Kiểm tra lần cuối: tháng 11/2026.

Khi viết doc mới, bắt đầu từ:
  • Teams SDK: framework dành riêng cho agent trong Teams, nên chọn nếu bot chỉ chạy trong Teams. Theo tài liệu Microsoft có gói tương thích để giữ handler Bot Framework cũ và chỉ đổi adapter, nên đây là đường di chuyển ít việc nhất cho bot v4.
  • Microsoft 365 Agents SDK: chọn nếu cần agent đa kênh. Cần .NET 8 trở lên, đổi namespace và package (ví dụ Microsoft.Bot.Builder.Integration.AspNet.Core sang Microsoft.Agents.Hosting.AspNetCore), serialization chuyển từ Newtonsoft sang System.Text.Json, một số thứ như Adaptive Dialogs không được mang sang.

Còn dùng được: phần giải thích cách Teams định tuyến, manifest, Azure Bot registration, luồng task/fetch và task/submit, lưu conversation reference, gửi và cập nhật message ngoài một turn. Đây là hành vi của Teams và Azure Bot Service. Không nên chép: tên class, package và code mẫu. Đối chiếu với tài liệu migration trước khi áp dụng.

Three moving parts, same as always. You never talk to Teams directly — everything is relayed through Azure Bot Service, which authenticates both sides and forwards activities to your endpoint.

How an incoming request is routed

The CloudAdapter validates the JWT and deserialises the activity, then calls your bot's OnTurnAsync. TeamsActivityHandler dispatches based on activity.Type and activity.Name — you override only the methods you care about.

bot.OnTurnAsync(ITurnContext) ├─ activity.Type = "message" ──→ OnMessageActivityAsync() ├─ activity.Type = "conversationUpdate" ──→ OnConversationUpdateActivityAsync() │ ├─ [Teams] members added ──→ OnTeamsMembersAddedAsync() │ └─ [Teams] members removed ──→ OnTeamsMembersRemovedAsync() └─ activity.Type = "invoke" ──→ OnInvokeActivityAsync() ├─ activity.Name = "task/fetch" ──→ OnTeamsTaskModuleFetchAsync() ├─ activity.Name = "task/submit" ──→ OnTeamsTaskModuleSubmitAsync() └─ activity.Name = "cardAction.invoke" → OnTeamsCardActionInvokeAsync()

Migration Reference

v3 → v4: What Changed

📦
Bot Framework SDK archived (January 2026)

The Microsoft.Bot.Builder.* v4 NuGet packages were archived by Microsoft on January 5, 2026 (support ceased December 31, 2025). They still work and Teams continues to support them — no breaking changes planned. For truly greenfield projects Microsoft points to the Microsoft 365 Agents SDK (aka.ms/agents). This guide covers Bot Framework v4 as it remains the best-documented path for task modules and Adaptive Cards today.

What stayed exactly the same

  • The /api/messages endpoint path — Azure Bot Service still POSTs here
  • The Activity JSON wire format — same schema, same fields
  • The task/fetch + task/submit protocol — same payload structure, same 5-second limit
  • The Adaptive Card JSON schema — same version strings, same validation properties
  • Azure Bot Service registration — same portal steps, same App ID + Client Secret model
  • Teams app manifest — same JSON structure, same sideloading process
  • Dev Tunnels setup for local development
  • ServiceUrl is still region-specific — still must not be hardcoded

AdapterWithErrorHandler.cs

C#using Microsoft.Bot.Builder.Integration.AspNet.Core;
using Microsoft.Bot.Connector.Authentication;

public class AdapterWithErrorHandler : CloudAdapter
{
    public AdapterWithErrorHandler(
        BotFrameworkAuthentication auth,
        ILogger<IBotFrameworkHttpAdapter> logger)
        : base(auth, logger)
    {
        OnTurnError = async (turnContext, exception) =>
        {
            logger.LogError(exception, "[OnTurnError] {Message}", exception.Message);
            await turnContext.SendActivityAsync("The bot encountered an error.");
            await turnContext.TraceActivityAsync(
                "OnTurnError Trace", exception.Message,
                "https://www.botframework.com/schemas/error", "TurnError");
        };
    }
}

Program.cs

C# — Program.csusing Microsoft.Bot.Builder;
using Microsoft.Bot.Builder.Integration.AspNet.Core;
using Microsoft.Bot.Connector.Authentication;
using System.Collections.Concurrent;

var builder = WebApplication.CreateBuilder(args);

// Reads MicrosoftAppId/Password/Type/TenantId from appsettings.json
// and performs JWT validation inside the adapter automatically
builder.Services.AddSingleton<BotFrameworkAuthentication,
    ConfigurationBotFrameworkAuthentication>();

// CloudAdapter is the current recommended adapter
builder.Services.AddSingleton<IBotFrameworkHttpAdapter, AdapterWithErrorHandler>();

// Also register as BotAdapter for clean proactive-messaging injection (optional)
builder.Services.AddSingleton<BotAdapter>(
    sp => (BotAdapter)sp.GetRequiredService<IBotFrameworkHttpAdapter>());

// In-memory ConversationReference store — replace with DB in production
builder.Services.AddSingleton<ConcurrentDictionary<string, ConversationReference>>();

// Transient: fresh bot instance per turn
builder.Services.AddTransient<IBot, MyTeamsBot>();

// Extra controllers (e.g. /api/notify for proactive triggers)
builder.Services.AddControllers();

var app = builder.Build();
app.UseRouting();
app.MapControllers();

// The single Teams bot endpoint — all activity types (message, invoke, etc.) arrive here
app.MapPost("/api/messages", async (
    HttpRequest req, HttpResponse res,
    IBotFrameworkHttpAdapter adapter, IBot bot) =>
{
    await adapter.ProcessAsync(req, res, bot);
});

app.Run();
✅
Verify the route is registered

Run the project and navigate to https://localhost:<port>/api/messages in a browser. You should get HTTP 405 Method Not Allowed — that means the route is wired up and waiting for a POST. A 404 means app.MapPost isn't being hit.

devtunnel create my-bot-tunnel --allow-anonymous

🔒
Why --allow-anonymous is safe here

Azure Bot Service cannot add custom request headers to its outbound call to your endpoint — it only POSTs with its own Bot Framework JWT in the Authorization header. Token-based tunnel access (devtunnel token) or Entra-based access would therefore block Azure Bot Service itself from reaching your bot.

The real security layer is the CloudAdapter: any request without a valid Bot Framework JWT signed with your MicrosoftAppId is rejected with HTTP 401 before your code runs. The tunnel URL is also a non-guessable random string — not publicly discoverable.

ApproachWorks with Azure Bot Service?Actual security
--allow-anonymous✅ YesProtected by CloudAdapter JWT validation
Token-based (devtunnel token)❌ No — Azure can't pass the headerN/A
Entra (--tenant)❌ No — Azure can't do interactive loginN/A

Setup — Step 3

How Authentication Works

↗ Bot Framework v4 basics ↗ Azure Bot registration walkthrough

Authentication is service-to-service — it's not about the Teams user logging in. It's about Azure Bot Service proving its identity to your bot on every request via a Bot Framework JWT. The CloudAdapter validates this automatically. You write zero auth code.

1

User triggers an activity in Teams

Teams sends it to Azure Bot Service. Azure signs the forwarded request with a Bot Framework JWT and POSTs to /api/messages.

2

CloudAdapter.ProcessAsync validates the JWT

ConfigurationBotFrameworkAuthentication reads MicrosoftAppId / MicrosoftAppPassword / MicrosoftAppType from appsettings.json and checks: signature, audience (== your App ID), issuer (Bot Framework endpoint), expiry.

3

Invalid JWT → HTTP 401, your code never runs

Any caller that can't produce a valid Bot Framework JWT signed with your App ID is rejected at the adapter layer. This includes attackers hitting your tunnel URL.

4

Valid JWT → activity deserialised → OnTurnAsync called

The adapter calls bot.OnTurnAsync(turnContext, ct). TeamsActivityHandler dispatches to your typed override method.

✅
Nothing to implement

The two AddSingleton lines in Program.cs are all you need. ConfigurationBotFrameworkAuthentication reads your credentials and CloudAdapter does the validation on every request — no attributes, no middleware, no manual JWT parsing.

TeamsActivityHandler — Your Bot's Class

↗ Official C# sample (v4) ↗ Bot basics (Teams)

Your bot is a class that inherits from TeamsActivityHandler. You override virtual methods for each activity type you care about — the base class handles everything else, including routing and returning the correct HTTP response codes to Azure Bot Service.

Class hierarchy: ActivityHandler (Microsoft.Bot.Builder) → TeamsActivityHandler (Microsoft.Bot.Builder.Teams) → MyTeamsBot (your class)

Full bot skeleton

C# — MyTeamsBot.csusing Microsoft.Bot.Builder;
using Microsoft.Bot.Builder.Teams;
using Microsoft.Bot.Schema;
using Microsoft.Bot.Schema.Teams;
using Newtonsoft.Json.Linq;
using System.Collections.Concurrent;

public class MyTeamsBot : TeamsActivityHandler
{
    private readonly IConfiguration _config;
    private readonly ConcurrentDictionary<string, ConversationReference> _refs;

    public MyTeamsBot(
        IConfiguration config,
        ConcurrentDictionary<string, ConversationReference> refs)
    {
        _config = config;
        _refs   = refs;
    }

    // ── User sent a message ───────────────────────────────────────────────
    protected override async Task OnMessageActivityAsync(
        ITurnContext<IMessageActivity> turnContext,
        CancellationToken cancellationToken)
    {
        turnContext.Activity.RemoveRecipientMention(); // strips @mention in channels
        var text = turnContext.Activity.Text?.Trim() ?? string.Empty;

        await turnContext.SendActivityAsync(
            MessageFactory.Text($"You said: {text}"), cancellationToken);
    }

    // ── Conversation lifecycle — always capture ConversationReference ─────
    protected override Task OnConversationUpdateActivityAsync(
        ITurnContext<IConversationUpdateActivity> turnContext,
        CancellationToken cancellationToken)
    {
        CaptureConversationReference(turnContext.Activity);
        return base.OnConversationUpdateActivityAsync(turnContext, cancellationToken);
    }

    // ── Bot installed (recommended over OnTeamsMembersAddedAsync) ─────────
    protected override async Task OnInstallationUpdateAddAsync(
        ITurnContext<IInstallationUpdateActivity> turnContext,
        CancellationToken cancellationToken)
    {
        CaptureConversationReference(turnContext.Activity as Activity);
        await turnContext.SendActivityAsync(
            MessageFactory.Text("Hi! I'm ready."), cancellationToken);
    }

    // ── Bot uninstalled ───────────────────────────────────────────────────
    protected override Task OnInstallationUpdateRemoveAsync(
        ITurnContext<IInstallationUpdateActivity> turnContext,
        CancellationToken cancellationToken)
    {
        var userId = turnContext.Activity.From?.Id;
        if (userId != null) _refs.TryRemove(userId, out _);
        return Task.CompletedTask;
    }

    // ── task/fetch → covered in Step 2 ───────────────────────────────────
    protected override Task<TaskModuleResponse> OnTeamsTaskModuleFetchAsync(
        ITurnContext<IInvokeActivity> turnContext,
        TaskModuleRequest taskModuleRequest,
        CancellationToken cancellationToken)
        => throw new NotImplementedException();

    // ── task/submit → covered in Step 4 ──────────────────────────────────
    protected override Task<TaskModuleResponse> OnTeamsTaskModuleSubmitAsync(
        ITurnContext<IInvokeActivity> turnContext,
        TaskModuleRequest taskModuleRequest,
        CancellationToken cancellationToken)
        => throw new NotImplementedException();

    // ── Helper ────────────────────────────────────────────────────────────
    private void CaptureConversationReference(Activity activity)
    {
        var reference = activity.GetConversationReference();
        _refs.AddOrUpdate(reference.User.Id, reference, (_, _) => reference);
    }
}
Foundation

Storing Conversation Reference

Before your bot can send proactive messages or update a previously posted card, it needs a ConversationReference. This is a single object capturing everything required to resume a conversation — it arrives on every Activity your bot receives via activity.GetConversationReference(). Persist it during early interactions so you can use it later when no turn is active.

What ConversationReference contains

PropertyTypeWhat it's used for
User{ Id, Name }The Teams user who triggered the activity
Bot{ Id, Name }Your bot's identity
Conversation{ Id, IsGroup }The conversation/chat thread ID
ChannelId"msteams"Always "msteams" for Teams
ServiceUrlstringRegion-specific relay URL. Never hardcode. Always store from incoming activity.
⚠️
ServiceUrl is region-specific and can change

It looks like https://smba.trafficmanager.net/amer/ but the suffix changes by tenant and Microsoft can move regions. Always store the value from the incoming activity and use the stored value for proactive calls. Never hardcode it.

When does it first arrive?

activity.GetConversationReference() is available on every activity your handlers receive. The best moments to capture and persist it:

  • OnInstallationUpdateAddAsync — fires when the bot is installed. Recommended by Microsoft for install detection. Has a clear Action = "add" vs "remove" distinction.
  • OnConversationUpdateActivityAsync — fires on conversation lifecycle events. Good as a defensive layer to keep the reference fresh.
  • OnMessageActivityAsync — fires on every user message. Good as a fallback to refresh the stored reference.
All cases: var reference = activity.GetConversationReference(); — it's a method call on the Activity object your handler already receives. Nothing special to do.

Persisting to a database

Task Module — Step 1

Send a Trigger Card with a Button

↗ Task module from bot

Post an Adaptive Card to the conversation. The card has an Action.Submit button with msteams.type = "task/fetch" — that tells Teams to open a modal instead of performing a normal form submit. Save the returned ActivityId — you'll need it to update the card after processing.

JSON — Adaptive Card{

  "type": "AdaptiveCard",
  "version": "1.3",
  "body": [{
    "type": "TextBlock",
    "text": "Item #42 is ready for review.",
    "weight": "Bolder",

C#private async Task SendTriggerCardAsync(
    ITurnContext turnContext, string itemId, string itemName, CancellationToken ct)
{
    var cardJson = $@"{{
      ""$schema"": ""http://adaptivecards.io/schemas/adaptive-card.json"",
      ""type"": ""AdaptiveCard"",
      ""version"": ""1.3"",
      ""body"": [{{ ""type"": ""TextBlock"", ""text"": ""{itemName} needs attention."",
                    ""weight"": ""Bolder"", ""wrap"": true }}],
      ""actions"": [{{
        ""type"": ""Action.Submit"", ""title"": ""Open Form"",
        ""data"": {{ ""msteams"": {{ ""type"": ""task/fetch"" }}, ""itemId"": ""{itemId}"" }}
      }}]
    }}";

    var attachment = new Attachment
    {
        ContentType = "application/vnd.microsoft.card.adaptive",
        Content     = JsonConvert.DeserializeObject(cardJson)
    };

    // Save ActivityId — needed later to update the card with the result
    var response   = await turnContext.SendActivityAsync(
        MessageFactory.Attachment(attachment), ct);
    var activityId = response.Id;

    await _db.SaveCardActivityIdAsync(turnContext.Activity.From.Id, activityId);
}
💡
Store the ActivityId from SendActivityAsync

The response object from turnContext.SendActivityAsync() contains an Id property — that's the ActivityId of the message just sent. Persist it alongside the ConversationReference. You'll pass it to UpdateActivityAsync later to replace the card in-place rather than posting a new message.

Task Module — Step 2

task/fetch — Return the Modal Card

↗ Task module overview ↗ Task module from bot

When the user clicks the button, Teams fires an invoke activity at your bot. OnTeamsTaskModuleFetchAsync is called. Build your card, fill in the TaskModuleTaskInfo, and return — the entire method must complete within 5 seconds.

⚠️

Task Module — Step 4

task/submit — Read User Input

↗ Task module from bot

After the user passes client-side validation and clicks Submit, Teams posts a task/submit invoke. All field values are in taskModuleRequest.Data, keyed by the id you set on each input element. Return a TaskModuleResponse quickly — kick off heavy processing as fire-and-forget.

C#protected override async Task<TaskModuleResponse> OnTeamsTaskModuleSubmitAsync(
    ITurnContext<IInvokeActivity> turnContext,
    TaskModuleRequest taskModuleRequest,
    CancellationToken cancellationToken)
{
    var data = JObject.FromObject(taskModuleRequest.Data);

    // ── Read fields (ALL values arrive as strings) ────────────────────
    var fullName    = data["fullName"]?.ToString()   ?? string.Empty;
    var quantityStr = data["quantity"]?.ToString()   ?? string.Empty;
    var categories  = data["categories"]?.ToString() ?? string.Empty; // "a,b,c"
    var confirmed   = data["confirmed"]?.ToString()  == "true";       // Toggle → string!

    // ── Server-side validation (client validation can be bypassed) ────
    if (string.IsNullOrWhiteSpace(fullName))
        return MessageResponse("Validation failed: Name is required.");

    if (!int.TryParse(quantityStr, out var quantity) || quantity < 1)
        return MessageResponse("Validation failed: Quantity must be 1 or greater.");

    var selectedCategories = categories
        .Split(',', StringSplitOptions.RemoveEmptyEntries)
        .Select(s => s.Trim()).ToList();

    if (!selectedCategories.Any())
        return MessageResponse("Validation failed: Select at least one category.");

    // ── Capture before fire-and-forget (ITurnContext won't exist later) ─
    var convRef    = turnContext.Activity.GetConversationReference();
    var activityId = await _db.GetCardActivityIdAsync(convRef.User.Id);

    // ── Fire-and-forget: return immediately to close the modal ─────────
    _ = Task.Run(async () =>
    {
        try
        {
            await ProcessSubmissionAsync(fullName, quantity, selectedCategories);
            await UpdateTriggerCardAsync(convRef, activityId, success: true);
        }
        catch
        {
            await UpdateTriggerCardAsync(convRef, activityId, success: false);
        }
    });

    // Return empty response — closes the modal with no popup message
    return new TaskModuleResponse();
}

private static TaskModuleResponse MessageResponse(string text) =>
    new TaskModuleResponse
    {
        Task = new TaskModuleMessageResponse { Type = "message", Value = text }
    };

Task Module — Step 5

Response Patterns for task/submit

↗ Task module overview ↗ Task module from bot

Four choices for what to return from OnTeamsTaskModuleSubmitAsync. Pick based on how long processing takes and what the user needs to see.

Pattern 1
Close silently

Return new TaskModuleResponse(). Modal closes instantly. Best for fire-and-forget — result appears by updating the original card.

Pattern 2
Show message popup

Return a TaskModuleMessageResponse. Modal closes and a brief text popup is shown. Good for quick acknowledgements.

Pattern 3
Continue (wizard)

Return a TaskModuleContinueResponse with a new TaskModuleTaskInfo. Modal stays open with new content. Good for multi-step flows.

Pattern 4
Continue (web page)

Return a TaskModuleContinueResponse with a Url. Modal content replaced with an HTML page. Good when step 2 needs richer UI.

Update the Original Message After Processing

When your background task completes, replace the trigger card in the chat with a result card. You need two things stored in your DB: the ConversationReference (to resume the conversation) and the ActivityId of the original card (to update it rather than post a new message).

C#private async Task UpdateTriggerCardAsync(
    ConversationReference convRef, string activityId, bool success)
{
    var resultJson = success ? BuildSuccessCard() : BuildFailureCard();
    var attachment = new Attachment
    {
        ContentType = "application/vnd.microsoft.card.adaptive",
        Content     = JsonConvert.DeserializeObject(resultJson)

            update.Id  = activityId; // ← identifies which message to replace

        },
        CancellationToken.None);
}

Proactive Messaging

Sending Messages Outside a Turn

↗ Proactive messaging (Teams) ↗ Proactive messaging (general)

Your bot initiates a message without a user having triggered an activity first — e.g. an external system event, a scheduled job, or the result of a long background task. You need the stored ConversationReference and BotAdapter.ContinueConversationAsync.

The pattern

1

During any normal turn — capture and persist ConversationReference

Do this in OnTeamsMembersAddedAsync and/or OnConversationUpdateActivityAsync. Covered in the "Storing Conv. Reference" section.

2

External trigger arrives

An HTTP call hits your /api/notify controller, a background job fires, a message queue event is received, etc.

3

Load ConversationReference and call ContinueConversationAsync

The adapter creates a synthetic turn context. Inside the callback you have a full ITurnContext — call SendActivityAsync, UpdateActivityAsync, etc. normally.

[ApiController]
public class NotifyController : ControllerBase
{
    private readonly BotAdapter    _adapter;
    private readonly IConfiguration _config;
    private readonly IConversationStore _store;

    public NotifyController(
        BotAdapter adapter, IConfiguration config, IConversationStore store)
    {

        _config  = config;
        _store   = store;
    }

    [HttpPost("{userId}")]
    public async Task<IActionResult> NotifyUser(string userId, [FromBody] string message)
    {
        var refJson = await _store.GetConversationRefJsonAsync(userId);
        if (refJson is null)
            return NotFound("User has not interacted with the bot.");

        var reference  = JsonConvert.DeserializeObject<ConversationReference>(refJson)!;
        var attachment = BuildNotificationCard(message);

        await _adapter.ContinueConversationAsync(
            _config["MicrosoftAppId"]!,
            reference,
            async (turnContext, ct) =>
            {
                await turnContext.SendActivityAsync(
                    MessageFactory.Attachment(attachment), ct);
            },
            default);

        return Ok();
    }
}

            ? BuildResultCardJson("Done — processed successfully.", "Good")
            : BuildResultCardJson("Something went wrong. Please try again.", "Attention");

        var attachment = new Attachment
        {
            ContentType = "application/vnd.microsoft.card.adaptive",
            Content     = JsonConvert.DeserializeObject(resultJson)
        };

        // Use the injected BotAdapter (registered in Program.cs)
        var adapter = (BotAdapter)HttpContext.RequestServices
            .GetRequiredService<IBotFrameworkHttpAdapter>();

        await adapter.ContinueConversationAsync(
            _config["MicrosoftAppId"]!,
            convRef,
            async (turnContext, ct) =>
            {
                var update = MessageFactory.Attachment(attachment);
                update.Id  = activityId;
                await turnContext.UpdateActivityAsync(update, ct);
            },
            CancellationToken.None);
    }

    private static string BuildResultCardJson(string message, string color)
    {
        return $@"{{
          ""type"": ""AdaptiveCard"", ""version"": ""1.3"",
          ""body"": [{{ ""type"": ""TextBlock"", ""text"": ""{message}"",
                        ""color"": ""{color}"", ""weight"": ""Bolder"", ""wrap"": true }}]
        }}";
    }

    // ═══════════════════════════════════════════════════════════════════════
    // HELPERS
    // ═══════════════════════════════════════════════════════════════════════

    private void CaptureConversationReference(Activity activity)
    {
        var reference = activity.GetConversationReference();
        _refs.AddOrUpdate(reference.User.Id, reference, (_, _) => reference);
    }

    private static TaskModuleResponse MessageResponse(string text) =>
        new TaskModuleResponse
        {
            Task = new TaskModuleMessageResponse { Value = text }
        };

using Microsoft.Bot.Builder;
using Microsoft.Bot.Builder.Integration.AspNet.Core;
using Microsoft.Bot.Schema;
using Newtonsoft.Json;
using System.Collections.Concurrent;

/// Your own API endpoint — not a Teams endpoint.
/// Your backend (job scheduler, webhook, etc.) calls this to trigger a proactive message.
[Route("api/notify")]
[ApiController]
public class NotifyController : ControllerBase
{
    private readonly BotAdapter _adapter;
    private readonly IConfiguration _config;
    private readonly ConcurrentDictionary<string, ConversationReference> _refs;

    public NotifyController(
        BotAdapter adapter,
        IConfiguration config,
        ConcurrentDictionary<string, ConversationReference> refs)
    {
        _adapter = adapter;
        _config  = config;
        _refs    = refs;
    }

    [HttpPost("{userId}")]
    public async Task<IActionResult> NotifyUser(string userId, [FromBody] string message)
    {
        if (!_refs.TryGetValue(userId, out var reference))
            return NotFound("User has not interacted with the bot.");

        var cardJson = $@"{{
          ""type"": ""AdaptiveCard"", ""version"": ""1.3"",
          ""body"": [{{ ""type"": ""TextBlock"", ""text"": ""{message}"",
                        ""wrap"": true, ""weight"": ""Bolder"" }}],
          ""actions"": [{{
            ""type"": ""Action.Submit"", ""title"": ""Open Form"",
            ""data"": {{ ""msteams"": {{ ""type"": ""task/fetch"" }} }}
          }}]
        }}";

        var attachment = new Attachment
        {
            ContentType = "application/vnd.microsoft.card.adaptive",
            Content     = JsonConvert.DeserializeObject(cardJson)
        };

        await _adapter.ContinueConversationAsync(
            _config["MicrosoftAppId"]!,
            reference,
            async (turnContext, ct) =>
            {
                await turnContext.SendActivityAsync(
                    MessageFactory.Attachment(attachment), ct);
            },
            default);

        return Ok();
    }
}
